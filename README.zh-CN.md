# FAQ：把 WebDAV / NAS 挂成 Windows 盘符

下面这些是我自己搭环境时踩过的坑，加上别人问过我、我也答过的问题。先做利益披露：ScsDrive 是我们做的（https://drive.scsoi.com/），所以提到产品的地方请当成有倾向。下面的机制解释不依赖谁写的。

## 「映射网络驱动器」和真正的盘符是一回事吗？

不是，这是最大的误解来源。

Windows 自带的**映射网络驱动器**（WebClient 服务）创建的是*网络驱动器*：它出现在**网络位置**下面，走的是重定向器，坚持要本地路径的程序会拒绝它或者行为异常。

而**真实本地卷**会出现在**此电脑 → 设备和驱动器**里，带着一个正常的盘符（D:、E:……），行为跟内置磁盘一样。很多人说「我要盘符，不要网络共享」，要的就是这个区别。

## 挂载需要管理员权限吗？

挂载本身不需要，用你自己的 Windows 账号、在你自己的会话里挂就行。

有一个容易被含糊过去的点：**首次启动**时，程序会自行配置它需要的开源用户态文件系统驱动（Dokany，LGPL）。它不是内核组件，也不用你安装或配置什么——但这意味着第一次启动做的事比一条 `subst` 多。

## 重启之后还在吗？备份服务能看到吗？

这块我折腾最久，一段话说清。

挂载归属于**创建它的那个 Windows 会话**。由此有两个实际结果：

- 跑在 **Session 0**（Windows 为系统服务保留的隔离会话）里的服务和计划任务**看不到**这个盘符。你的桌面上明明有这个盘，但这样启动的备份工具或脚本会报路径不存在。请改成在交互式会话里、用拥有该挂载的同一个账号运行。
- 重启之后盘符在开机阶段**并不存在**。客户端可以在你再次登录时重建挂载，所以如果脚本跑在你登录之前，它就会跑在挂载存在之前。

## 传输中途断网会怎样？

网络恢复后客户端会自己重连，启动时也会恢复挂载。但它没法保证「写到一半被打断的那一个文件一定完好」——任何跑在不稳定链路上的文件系统都是这样，连接死在写入中途的话，那个文件值得单独看一眼。

## 我的 NAS 能用吗？

只要支持 **WebDAV** 就行：开启 WebDAV 的群晖、威联通，Nextcloud，AList / OpenList，自建 WebDAV 服务，以及通过 WebDAV 网关暴露出来的云盘都可以。每个挂载的服务有自己的盘符，可以同时挂好几个而不撞字母。
